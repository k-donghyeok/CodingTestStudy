lambda 표현식
	함수적 프로그래밍의 형태로 재사용 가능한 코드 블록
	
	타겟타입과 @FunctionalInterface
	lambda 식이 할당되는 인터페이스를 lambda 식의 타겟 타입이라 함
	왜 타겟 타입은 abstract 메서드가 반드시 하나만 존재해야하는가
	
	@FunctionalInterface
	컴파일러가 재정의해야 하는 abstract method 가 하나만 있음을 체크

	인터페이스에 재정의해야하는 추상메서드가 2개이상이면? 익명의 inner class 사용
	
	@FunctionalInterface 에 대한 구현체 작성법
	() ->{}
	매개변수 타입은 런타임시 대입되는 값에 따라 자동 인식 되므로 일반적으로 생략함
	매개변수 및 실행문이 하나일 때는 변수 및 실행문의 괄호, ';' 생략가능
	리턴문만 있는경우(당연히 하나의 문장만 존재) 중괄호와 return 을 생략할 수있음

	함수형 인터페이스 타입이 어떻게 람다식으로 작성이 가능할까? 타입과 메서드의 추정

	메서드 참조 
		람다 실행문 내부에서 다른 함수 하나만 을 실행 하는 경우 :: 연산자를 이용해 기존메서드 참조
		

함수형 프로그래밍
	함수의 형태는 함수형 인터페이스로 ,구현은 람다식으로 작성

표준 함수형 interface
	람다식을 사용하기위해서 함수형 인터페이스를 생성하지 말라고 미리 만들어둔 인터페이스
	자주 사용되는 함수의 구조를 표준 interface 로 java.utill.function package 에 정의
	6개 종류가 있고 
	
	Runnable 계열 -> 단순실행처리

	Consumer 계열 ->파라미터 있고 return 이없는 형태
		Bi : 파라미터가 2개인 경우 접두사
	
	Supplier 계열 -> 파라미터는 없고 return 이 있는 형태
	
	
	Function 계열 -> 파라미터 와 return 이 있는 형태

	Operator 계열 -> 파라미터와 return  이 있는 형태

	Predicate 계열 -> 파라미터 있고 boolean 타입을 리턴 하는 형태

Optional<T> : T타입의 객체에 대한 wrapper
	객체가 있을 수도 있고 없을 수도 있는 상태를 나타내는 객체



stream api 
	배열 및 collection 의 요소를 하나씩 참조해서 처리하는 목적
	람다와 내부 반복자를 이용해 요소를 다루는 코드를 간결화
	역할 및 특징
		컬렉션 배열 등 데이터 소스에 대한 공통된 접근 방식 제공
		손쉬운 병렬 처리

	맵/리듀스 모델 지원
	맵 : 데이터를 작은 단위(chunk) 로 나누어(splitting) 지정된 함수를 적용(mapping)처리
	리듀스 : 결과를 모아서 최종 결과를 생성 

	중간처리와 최종처리를 조합해서 사용
	중간처리 : 매핑,필터링,정렬 등 *가공처리*
	최종처리 : 반복,카운팅,평균,총합 등의 *집계처리*

	각각의 중간처리는 새로운 스트림을 리턴하여 *chaining 패턴* 적용 -> 기존 스트림의 내용을 수정하지 않음
	한번 최종처리가 끝난 스트림은 재사용 불가

	종류
	stream , Intstream , Longstream , Doublestream

	stream 은 객체를 위한스트림 나머지는 각각 이름에해당하는 기본형 데이터 처리를 위한 스트림
	
	중간처리는 최종처리가 진행될때까지 지연된다

	근데 메인 스레드에서 future 객체로 쓰레드 작업 결과값을 받으려고 하면 

	메인 스레드가 join() 상태가 되어서 결과값을 모두 받을때까지 실행되지않는다

	따라서 별도의 스레드를 하나 생성한후 그 스레드 안에서 결과값을 받도록해야지
	main 스레드가 join() 되지 않음
