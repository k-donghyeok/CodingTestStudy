제네릭
	뭐든지 담을수있으면 담을때는 편하지만 뺄 때는 번거롭다->어떤것을 담을것인지 한정 -> 담을때는 번거롭지만 꺼낼때 편하다

	목적 : 다양한 타입의 객체를 다루는 메소드 컬렉션 클래스에서 """"컴파일""""" 타임에 타입을 체크하겠다

		이전에는 언제 타입을 체크했지? 런타임때 instacne of 로 실제 메모리의 값을 확인했음

		미리 사용할 타입을 명시해서 형 변환을 하지 않아도 되게함으로 객체의 타입에 대한 안전성 향상 및
		형 변환의 번거로움 감소

	사용법 : 클래스 또는 인터페이스 선언시에 <> 에 "타입 파라미터"(T) 표시
	
	주의사항 : raw type 사용시 @supprssWarnings 지양할것
			타입 파라미터는 인스턴스 레벨에서 결정됨
				클래스 레벨의 static 멤버에서는 사용할수 없음 

			raw타입 객체의 형 변환 주의
				

			Generic 은 컴파일 타임에 지정한 타입으로 존재 -> 런타임에는 타입 정보 소거 runtime 에 동작하는 new,instanceof 키				워드 사용불가

			Generic 타입의 배열 생성불가 ->배열은 runtime에 객체의 정보를 유지하고 동일한 타입의 객체만 처리함 컬렉션 사용권장
		
	한정형 형인자
		필요에 따라 구체적인 타입 제한 필요
			type 파라미터 선언뒤 extends 와 함께 상위 타입 명시 
			인터페이스로 제한할 경우도 extends 사용 클래스와 함께 인터페이스 제약 조건을 이용할 경우 & 로 연결

	제네릭 메서드
		파라미터와 리턴타입으로 type parameter 를 갖는 메서드

	와일드 카드(?) 자료형
		제네릭 타입 변수 선언 시 실제 type parameter 가 무엇인지 모르거나 싱경쓰고 싶지 않을 경우

		? extends 클래스  자료를 꺼낼때 좋음
		? super 클래스 자료를 넣을때 좋음
