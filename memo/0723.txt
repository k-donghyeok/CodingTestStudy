abstract class
	
 	다른 클래스 들 마다 중복 부분을 하나의 클래스를 만들어 상속 시켜 코드의 중복을 줄임

	
	조상 클래스에서 메서드를 만들어두었지만 자식 클래스에서 반드시 재정의 하여 사용하기 때문에
	조상 클래스 에서 구현이 무의미한 메서드

	abstract method 디자인 패턴

	abstract 클래스는 상속 전용의 클래스
		추상클래스의 추상메서드는 자식에서 반드시 재정의 해야함
		클래스에 구현부가 없는 메서드가 있으므로 객체를 생성할수없음
		하지만 상위 클래스 타입으로 자식을 참조는 가능 (다형성 적용)

	조상 클래스에서 상속받은 추상 메서드를 재정의 하지 않은 경우
		클래스 내부에 추상 메서드가 있는 상황이므로 자식 클래스는 추상 클래스로 선언 되어야함

	추상 클래스는 메서드 구현의 강제를 통해 프로그램의 안정성 향상

	uml 다이어그램에서 추상클래스는 비스듬히 기울어져있음

interface

	개념 : 서로 다른 두 시스템 장치 소프트웨어 따위를 서로 이어 주는 부분 또는 그런 접속 장치
	일반 메서드는 모두 abstract 형태 jdk8 부터 default ,static method 추가
	
	모든 멤버변수는 public static final 이며 생략가능
	모든 메서드는 public abstract 이며 생략가능
	
	인터페이스는 인터페이스 끼리 상속이 가능하고 다중상속이 가능
	
	인터페이스 구현 implements 키워드 사용해서 인터페이스 구현가능

	구현한 클래스는
		모든 abstract 메서드를 override 해서 구현하거나
		구현하지 않을경우 abstract 클래스로 표시해야함
		여러개의 interface implements 가능
		다형성은 조상 클래스 뿐 아니라 조상 인터페이스도 가능
		인터페이스와 클래스의  관계도 is a 관계이지만 좀더 세부적으로 is able to 라고한다

	필요성
		1.구현의 강제로 표준화 처리 -> 손쉬운 모듈 교체 지원
		2. 서로 상속의 관계가 없는 클래스 들에게 인터페이스를 통한 관계부여로 다형성 확장
		3.독립적인 프로그래밍으로 개발 기간 단축
		
default method 
	인터페이스에 선언된 구현부가 있는 일반 메서드
		기존에 interface 기반으로 동작하는 라이브러리의 interface에 추가해야하는 기능이발생
		abstract 메서드는 모든 구현테들이 추가되는 메서드를 override 해야함
		default 메서드는 abstract 가 아니므로 반드시 구현 해야 할 필요는없어짐 -> 근데 그럼 재정의 강제를 못하는데? 추가 해야하는 기능이 재정의 를 강제해야하면? 그냥 인터페이스를 구현받은 모든 클래스들을 수정해 줘야하나?

		충돌발생시 우선순위
		인터페이스와 클래스 를 상속과 구현 받은경우에 충돌이면 클래스에서 상속받은 메서드가 이긴다

		인터페이스와 인터페이스 2개 에서 충돌이일어나면 (메서드의 defalut 유무는 상관없음) 구현 받은 클래스에서 반드시 재정의 		하는것으로 해결
