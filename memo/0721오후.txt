상속

상위 클래스의 생성자와 초기화 블록은 상속하지 않는다

extends 

상속의 방점은 물려받은것이아니라 확장에있다 

상속의 관계는 is a 관계 라고함

자바는 단일상속만 지원함
	대신 interface 와 포함관계(has a)관계로 극복


포함관계
	

상속이냐 포함이냐 그것이 문제로다
-> 어떤 클래스를 상속 받고 어떤 클래스를 포함해야 하는가?
	->문법적인 문제가 아니라 프로젝트의 관점 문제
		->상속 : is a 관계가 성립하는가? -> SpiderMan is Person
		->포함 : has a 관계가 성립하는가? -> SpiderMan has Spider

나는 자식을 선택할수 없는가?
Sealed class -> 내가 관리하는 특정 클래스 에게만 상속가능 	자바17버전 부터 추가
	목적 : 상속받을 클래스를 제한하고싶을때
	작성법 : 	sealed class 이름 permits 자식, 자식{}
			(final,sealed,non-sealed) class 이름 extends 부모{}
				sealed 클래스를 직접 상속한 자식 클래스는 반드시 저 3개의 키워드 중 하나를 선택해야한다
					final -> 자신에서 상속을완전히 끝낸다
					sealed ->자신도 sealed 클래스가 된다 -> 허용된 클래스만 상속하도록 또 제한
					non-sealed -> 자신부터는 다시 일반 클래스 처럼 -> 자신부터는 다시 누구나 상속 가능하게


매서드 재정의
	오버라이딩 조건 
		메서드 선언부가 같아야한다
		접근 제한자는 부모보다 범위가 넓거나 같아야한다
		조상보다 더 큰 예외를던질수 없다

super 키워드 를 통해 조상 클래스 멤버 접근

메서드 내부 ->클래스 내부 -> 조상 클래스 내부

this() 가 해당 클래스의 다른 생성자를 호출하듯 super()는 조상 클래스의 생성자 호출

명시적으로 this() super() 호출하지 않는경우 컴파일러가 super() 삽입

Annotation
	->컴파일러,jvm프레임워크 등이 보는 주석
	
	@Override
		부모클래스의 메서드를 재정의 하는것이라고 컴파일러에게 알려줌

	패키지이름 + 클래스 이름 -> fully qualified name

제한자(modifer)

접근제한자
	public,protected,private
그외제한자
	static,final,abstract,synchronized

하나의 대상에 여러 제한자를 조합 가능하나 접근 제한자는 하나만사용가능

순서는 무관 관례적으로 접근제한자를 맨앞으로


final
	->마지막,더이상 바뀔수 없음
	final class -> 더 이상 확장할수없음 : 상속금지 -> 오버라이드 금지

	final method -> 더 이상 재 정의 할수없음 : 오버라이드 금지

	final variable -> 더 이상 값을 바꿀수 없음
		-blank final : 값이 할당되지 않은 멤버 변수 -> 생성자에서 1회 초기화 가능

		-static final : 단지 final 만 있으면 공용성이 없으므로 static 추가해서 공용으로 사용
