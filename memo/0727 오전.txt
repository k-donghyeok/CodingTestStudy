컬렉션
	배열 -> 동일한 타입의 데이터만 관리 가능 -> 그러면 타입이 다른 객체를 관리하기 위해서는 매번 다른 배열이 필요한가?
	모든 클래스는 Object를 상속받게하여 다형성을 이용해 Object 하나에 모든객체를 참조가 가능하게 함
	-> 하지만 담을때(참조할때) 는 편리하지만 빼낼때는 Object 로만가져 올수있음
	-> 실제 담김 객체가 무엇인지 런타임에 instance of 연산자를 이용해 매번 확인 해야하는 번거로움이 있음
	-> 제네릭을 이용해 컴파일 타임에 저장하려는 타입을 제한하여 담긴 객체가 무엇인지 직관적으로 알수있음

	java.util 패키지에 존재
	
	List -> 순서가 있음 
		ArrayList 장단점 :배열 기반이므로 배열의 장단점을 그대로 가져감
			장점 : 동일한 크기의 데이터가 연속되어 구성되므로 접근 속도가 빠름
			단점 : 크기를 변경할수없어 추가,삭제 를 위해서 새로운 배열을 만들고 복사 해야함 

		LinkedList 각 요소를 node 로 정의하고 node 는 다음요소의 참조값과 데이터로 구성됨
			ListIterator -> 특정 인덱스 에서 기다렸다가 처리 처음 해당위치로 이동하는 비용은 동일 하지만 이후에는 계속 그 위치							에서 작업
			
	Set -> 순서가 없음
		hash -> 임의의 길이를 가진 데이터를 고정된 길이로 변환한 고유한 값
			해시 함수,해시 테이블,hashset 클래스 에서 equals 재정의시 hashcode 함수도 같이 재정의 해줘야하는이유
	Map ->key value (딕셔너리?)
		key,value를 entry로 묶어서 관리 key는 중복을 허락하지 않고 value는 중복을 허락
		내부적으로 Nodek,v> [] 로 데이터관리 배열의 index는 hash
		HashSet 도 내부적으로 는 HashMap 에 데이터 저장 -> key에 value 넣고 value에는 dummy 값 사용
		
		왜 Map 형식으로 저장된걸 Set형식으로 변경해서 전체요소 접근할까?(반복문 을돌릴까) entrySet()

불변 컬렉션
	List.of() -> 불변 List 
		null 저장시 런타임에러 발생
	Set.of() -> 불변 Set
		데이터 중복 또는 null 저장시 런타임 에러 발생
	Map.of -> 불변 Map
		최대 10개의 엔트리 까지 지원되며 null 키/값 불가

정렬
	정렬을 하려면 기준과 정렬방향이 필요하다
	정렬을 하려면 Comparable 인터페이스를 구현받은 클래스 들만 가능하다->String 과 Integer 클래스는 이미 Comparable 클래스	를 구현받고있음 
	Comparable 인터페이스는 compareTo 추상메서드 만 가지고 있는데 이 함수는 int 기본형을 반환하고 
	그 값의 크기는중요하지 않고 부호가 중요하다 양수:자리바꿈 음수:자리유지
	이 compareTo 함수를 재정의할때 클래스의 인스턴스 변수에 사전에 비교 가능한(int,String) 타입의 변수가 있다면 그것을 재사용	하거나 없다면 정렬을 위해 만들어서 사용해야함

	Comparator
		객체가 Comparable 을 구현하고 있지 않거나 사용자 정의 알고리즘으로 정렬 하려는 경우 
		(String 을 알파벳 순이아닌 글자 수 별로 정렬하려면?)
	
	클래스를 만들어서 까지 하기에는 이 기능이 잘사용되지 않을때
	일회용으로 객체를 사용하고싶을때 anonymous inner class 를 사용한다
	클래스 정의,객체 생성을 한번에 처리
